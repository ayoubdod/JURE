# JURE Internationalization (i18n)

JURE is a first-class multilingual product for **English (`en`)**, **French (`fr`)**, and **Arabic (`ar`)**.

## Architecture overview

| Surface | Locale source of truth | Translation store |
|---------|------------------------|-------------------|
| Marketing website | URL prefix `/en`, `/fr`, `/ar` | `src/marketing/**` content + SEO routes |
| Authenticated SaaS + auth | `localStorage["lang"]` (no route prefix) | `src/i18n/messages/{en,fr,ar}.ts` |

Both surfaces share the same storage key and locale identifiers so switching language on marketing carries into the app and vice versa.

**Do not introduce a second competing system** (extra LanguageContext / i18next alongside this). Extend this module.

## Supported locales

```ts
en | fr | ar
```

- Default / fallback: **English**
- RTL: Arabic sets `document.documentElement.dir = "rtl"` and `lang = "ar"`
- Fonts: Space Grotesk (Latin) + Noto Sans Arabic / Cairo stack when `lang="ar"` (see `index.html` / Tailwind)

## SaaS translation API

```tsx
import { useAppTranslation } from '@/i18n';

const { t, tf, lang, dir, enumLabel, apiError } = useAppTranslation();

t.sidebar.cases
tf(t.settings.languageCurrentLabel, { name: 'Français' })
enumLabel('caseStatus', 'OPEN') // → Open / Ouvert / مفتوح
apiError('CASE_NOT_FOUND')
```

Formatting helpers (locale-aware via `Intl`):

```ts
import { formatDate, formatCurrency, formatRelativeTime } from '@/i18n';
```

## Message structure

Messages live as typed TypeScript catalogs (not JSON) for compile-time safety:

```text
src/i18n/
  types.ts          # Lang, RTL, native labels, Intl tags
  locale.ts         # detect / persist / apply html lang+dir
  format.ts         # dates, numbers, currency, relative time
  glossary.ts       # controlled legal terminology
  enums.ts          # enum id → localized label
  errors.ts         # backend code → localized message
  messages/
    types.ts        # AppMessages interface
    en.ts | fr.ts | ar.ts
  index.ts          # useAppTranslation + re-exports
```

### Key naming

Prefer semantic keys:

```text
cases.actions.create
cases.status.open
cases.empty.title
auth.forgotSubmit
validation.invalidEmail
errors.codes.CASE_NOT_FOUND
```

Avoid positional keys (`text1`, `button3`).

### Legal glossary

Use `src/i18n/glossary.ts` for consistent legal product language (Case/Dossier/قضية, Hearing/Audience/جلسة, etc.). Do not invent alternate terms per screen.

### Enums

Store stable IDs in the database (`OPEN`, `CRIMINAL`, `high`). Translate only at presentation:

```ts
enumLabel('caseStatus', case.status)
```

### API errors

Prefer mapping backend codes through `apiError()` / `errors.codes`. Never show raw translation keys to users. Missing codes fall back to `errors.generic`.

## Fallback behavior

```text
Active locale → English
```

Missing keys should be caught by TypeScript (`AppMessages` must stay in sync across en/fr/ar) and by the audit script.

## Language switcher

Native endonyms:

- English
- Français
- العربية

Persistence priority:

1. Explicit user selection (`localStorage.lang`)
2. Browser language (first visit only)
3. English

## Marketing / SEO

- Locale-prefixed routes and hreflang remain under `src/marketing/`
- Keep SEO metadata translated (title, description, OG, Twitter, JSON-LD text)
- Do not add locale prefixes to `/dashboard/*`

## RTL guidelines

- Prefer logical CSS: `ms-`/`me-`, `ps-`/`pe-`, `start`/`end`, `text-start`
- Flip directional icons only (`ArrowLeft`/`ArrowRight`, chevrons) with `rtl:rotate-180`
- Do not flip search, settings, info, notification, or calendar icons

Marketing copy remains under `src/marketing/` (URL-locale + SEO).

## Adding a translation

1. Add the key to `src/i18n/messages/types.ts`
2. Add `en`, `fr`, and `ar` values in the three catalogs
3. Use `t.*` / `tf()` in the component
4. Run `npm run i18n:audit`

## Adding a new language

1. Extend `LOCALES` in `src/i18n/types.ts` and marketing `site.ts`
2. Add a new catalog file under `messages/`
3. Register it in `messages/index.ts`
4. Add native endonym + Intl tag
5. Update SEO/hreflang generation if public

## Testing

- Switch English → Français → العربية on auth + shell
- Confirm `<html lang>` / `dir` update
- Spot-check dates/currency with `formatDate` / `formatCurrency`
- Responsive RTL at 1440 / 768 / 390

## Audit

```bash
npm run i18n:audit
```

Reports structural key mismatches between `en` / `fr` / `ar` catalogs.
